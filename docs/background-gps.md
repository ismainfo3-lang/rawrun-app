# Sprint 02 — iPhone GPS test build
The UI and existing local data are preserved. Native Expo Location and TaskManager now provide one location source in foreground/background. The task is registered at module scope. A serialized local persistence path is shared by the UI and task; state is read before each update. Accepted GPS points are stored with segment boundaries so future route rendering does not connect paused or interrupted segments. No data leaves the device.
Requires a new iOS development build; update dependencies and lockfile using npm install, then npx expo install --check, npm test, npm run typecheck. Regenerate native configuration with non-clean prebuild (preserve signing changes), verify Info.plist contains location background mode and permission strings, install via Xcode/Expo. Keep bundle identifier unchanged. Grant Always location only when starting a run; denied permission prevents starting in this build. No foreground-only fallback yet.
Test physical iPhone: walk outdoors, lock 2–5 min, unlock, verify time and distance, pause and walk, resume, finish, confirm no more location indicator, open history, try airplane mode (GPS may still work), deny permission, force-close then reopen. Force quit is not guaranteed to track; restore pauses at last persisted checkpoint if registration is lost. Test process interruption and storage write races; serialized JS queue is not a cross-process transaction guarantee. No camera, push alerts or maps yet. Native compilation and actual background behavior are not yet verified.
